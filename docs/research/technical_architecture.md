## Key Question 1: Job data sources for Nigeria and remote-friendly roles

### Takeaway
No major free API covers Nigeria directly: Adzuna does not list Nigeria (its 19-country XML spec and 12-country MCP wrapper both stop at South Africa), Careerjet's published locale list has no en_NG, and Indeed's Publisher API is dead. The realistic Nigeria-plus-remote mix is (a) a paid Google-for-Jobs-derived aggregator (JSearch on RapidAPI, SerpApi Google Jobs, DataForSEO) for Nigerian local roles, (b) free remote boards with attribution terms (Remotive, Arbeitnow, RemoteOK), (c) direct partnerships or structured-data ingestion (JobPosting schema) from Jobberman/MyJobMag/HotNigerianJobs — none of which were found to publish a public API or RSS — and (d) a paid bulk vendor (TheirStack, Coresignal, Fantastic.jobs) once volume justifies it. Scraping LinkedIn/Indeed/Glassdoor directly (e.g., JobSpy) works technically but is a terms-of-service breach and should be avoided for a subscription product.

**De-duplication**
- Fraunhofer/Stuttgart paper (arXiv 2406.06257): aggregating postings across platforms requires duplicate detection because "the same job appears with different wording on different sites"; best results combine string comparison, deep text embeddings, and weighted skill-keyword lists; authors report a production tool. [snippet] — [arXiv 2406.06257](https://arxiv.org/abs/2406.06257v1)
- Textkernel uses shingling, min-wise permutations (MinHash) and an inverted index (Elasticsearch) to find candidates, and notes a simple similarity threshold is not enough because "true duplicates can have similarity as low as 37%", so it adds heuristics. [snippet] — [Textkernel: detecting near-duplicate job postings](https://www.textkernel.com/newsroom/online-job-postings-have-many-duplicates-but-how-can-you-detect-them-if-they-are-not-exact-copies-of-each-other/)
- Skeptric (practitioner series on job-ad dedup): ~7-word shingles reduce false positives on job ads; validate candidate pairs with edit distance, then group via connected components; template boilerplate causes large shared passages and reused ads for similar roles can look ~90% identical. [snippet] — [Skeptric: near-duplicate review](https://skeptric.com/near-duplicate-review); [Skeptric: MinHash LSH](https://skeptric.com/minhash-lsh)
- CareerBuilder's "Apollo" near-duplicate system for job ads was in production and benchmarked on precision/recall/F-score/runtime (IEEE ICDMW 2017). [snippet] — [IEEE ICDMW 2017](https://computer.org/csdl/proceedings-article/icdmw/2017/3800a177/12OmNC17hUn)

[snippet] — [Africa Check: Customs Service not recruiting](https://africacheck.org/fact-checks/meta-programme-fact-checks/scam-alert-nigerias-customs-service-isnt-recruiting-ignore); [Africa Check: Julius Berger not hiring](https://africacheck.org/fact-checks/meta-programme-fact-checks/nigerian-construction-giant-julius-berger-not-hiring-warns); [Innovation Village: FAAN warns](https://innovation-village.com/faan-warns-nigerians-against-fake-recruitment-offers/); [NGCareers: fake companies](https://ngcareers.com/fake-companies)

### Inferences
- For Nigerian local roles, the only programmatic sources found are Google-for-Jobs-derived aggregators (JSearch, SerpApi, DataForSEO), which index Jobberman/MyJobMag/LinkedIn/Indeed postings that carry JobPosting markup. Querying ~50-100 Nigerian role/location combinations daily on JSearch's $30/10k-request tier (or SerpApi Developer $50/5k) is roughly $30-130/month at launch. Verify current tiers on RapidAPI/SerpApi before budgeting.
- For remote-friendly roles, Remotive (free, 24-hour delay, must link back and credit) plus a bulk vendor later. Note Remotive's prohibition on using listings "to collect signups/email addresses" — a subscription-gated product that shows Remotive jobs behind a signup wall is at risk; keep Remotive jobs linked and attributed and consider their paid private API.
- A direct data partnership with Jobberman/MyJobMag (they have no public API) is the highest-value, lowest-legal-risk long-term source for Nigerian roles; the engineering team should build the ingestion layer source-agnostic (normalized JobPosting-like schema) so a partner feed can replace aggregator calls.
- Dedup design: canonicalize (strip HTML, lowercase, remove boilerplate), MinHash/LSH on ~7-word shingles for candidate recall, then confirm with an embedding cosine threshold plus structured-field agreement (company, title, location, date within N days); cluster by connected components and keep the earliest/most-complete record with all source URLs.
- Scam filter: a cheap rules layer (fee mentions, webmail-only contact, WhatsApp-only application, missing company domain, salary far above market, "no experience needed" + high pay) plus an LLM classifier on borderline cases, plus a domain/company registry whitelist (verified employer domains) and user reporting.

## Key Question 2: AI layer — CV generation, parsing, matching, reranking, vector storage

### Takeaway
Store CVs as structured JSON (JSON Resume is the de facto open schema; MIT-licensed and moved into the jsonresume.org monorepo), generate/tailor with an LLM using structured outputs, render to PDF via headless Chromium or react-pdf and to DOCX via the `docx` npm library, and match with a two-stage pipeline: cheap embeddings (OpenAI text-embedding-3-small at $0.02/M tokens or Cohere Embed v4 at ~$0.12/M) in pgvector for recall, then an LLM rerank of the top 20-30 per user. Resume Matcher (Apache-2.0), Reactive Resume (MIT) and OpenResume (AGPL-3.0) are reusable references; Resume Matcher's deterministic ATS score needs no LLM call. LLM rerank cost is on the order of $0.01-0.07 per user per week depending on model.

**Matching architecture (research and practice)**
- JobsPipe engineering blog (vendor, July 2026): three-stage pipeline — hard filters, vector recall, then cross-encoder or LLM rerank on the shortlist; normalize resumes and postings into structured summaries (skills, seniority, domain) before embedding; key embeddings to a content hash so stale postings get re-embedded. [snippet] — [JobsPipe: AI job matching](https://jobspipe.dev/blog/ai-job-matching.md)
- ConFit v3 (arXiv 2026): embedding-only ranking "lacks controllability and explainability", so an LLM re-ranks the top-N from an embedding model; resume-job labels are sparse and noisy. ConFit v2 (ACL Findings 2025) improves the encoder with LLM-generated hypothetical reference resumes and hard-negative mining, reporting +13.8% recall and +17.5% nDCG over ConFit v1. [snippet] — [ConFit v3](https://arxiv.org/pdf/2605.09760); [ConFit v2 (ACL 2025)](https://preview.aclanthology.org/setup/2025.findings-acl.661); [Multi-stage resume-job matching (arXiv 2604.02539)](https://arxiv.org/html/2604.02539v1)

**Vector database**
- pgvector: HNSW ("creates a multilayer graph", better speed-recall than IVFFlat, slower build, more memory, can be created on an empty table) and IVFFlat indexes; distances: L2 `<->`, inner product `<#>`, cosine `<=>`, L1 `<+>`, Hamming `<~>`, Jaccard `<%>`; indexed dims up to 2,000 for `vector`, 4,000 for `halfvec`, 64,000 for `bit`; `halfvec` stores half precision (2 × dims + 8 bytes); `binary_quantize` expression indexes recommended for smaller/faster indexes at scale with re-ranking on original vectors. [fetched] — [pgvector/pgvector](https://github.com/pgvector/pgvector)
- Cost/perf comparisons (2026 blogs, directional): "below ~5M vectors, pgvector on your existing database is almost always the cheapest production-grade choice"; "for most workloads under 10 million vectors, pgvector is now fully production grade"; Qdrant Cloud has a free single-node cluster (0.5 vCPU, 1 GB RAM, 4 GB disk) and ~$90-150/month for a 2-node 8 GB production cluster; Pinecone Serverless ~$70/month at 10M vectors with a $50/month minimum on production tiers; vendor-estimate vs real bill gap averages 2.5-4x. Tiger Data's pgvector/pgvectorscale comparison is vendor-biased. [snippet] — [spendark: vector database pricing](https://spendark.com/blog/vector-database-pricing/); [alexcloudstar: Vector DB comparison 2026](https://alexcloudstar.com/blog/vector-database-comparison-2026/); [Tiger Data: pgvector vs Qdrant](https://www.tigerdata.com/blog/pgvector-vs-qdrant)

### Inferences
- **Schema**: adopt JSON Resume as the canonical CV object (extend with `skills[].esco_uri`, `target_roles`, `location_prefs`, `salary_expectation_ngn`). Use LLM structured outputs to fill/tailor it; render via templates (Reactive Resume's MIT templates can be forked; avoid copying OpenResume code into a closed SaaS because of AGPL).
- **Parsing**: start with LLM-based parsing of extracted text (pdfminer/PDF.js + a structured-output call ≈ 2-4k input tokens ≈ $0.001-0.01 per CV on Haiku 5.5/GPT-5 mini); move to Affinda ($0.10/doc) only if accuracy on Nigerian CV formats proves inadequate.
- **Matching pipeline**: (1) nightly embed all new jobs once (shared cost, not per user); (2) per user, embed a "profile summary" (skills, titles, seniority, locations) and run pgvector cosine top-k=300 filtered by location/remote/seniority; (3) LLM rerank top 20-30 with a rubric (must-have skills, seniority fit, location/visa, salary) producing a 0-100 score and a one-line "why" for the email. Cache the user profile prefix (Anthropic prompt caching / OpenAI cached input) to cut input cost.
- **Token-cost estimate per user per week** (assumptions: job ≈ 600 tokens, profile ≈ 1,500 tokens, rubric ≈ 300 tokens, 10 jobs per rerank call, ~150 output tokens per job):
  - Rerank 30 jobs = 3 calls × (1,500 + 6,000 + 300) ≈ 23k input + ~4.5k output. Haiku 5.5: 23k×$0.10/M + 4.5k×$0.50/M ≈ **$0.0046/user/week**. GPT-5 mini: 23k×$0.25/M + 4.5k×$2/M ≈ **$0.015**. Sonnet 5.5: ≈ **$0.09**.
  - Rerank all 300 jobs with an LLM (no embedding stage): 10× the above → $0.05 (Haiku 5.5) to $0.90 (Sonnet 5.5) per user/week — this is why the embedding stage matters.
  - Embedding 300 jobs ≈ 180k tokens ≈ $0.0036 with text-embedding-3-small, and it is shared across all users (each job embedded once).
  - CV generation/tailoring: ≈ 3k input + 2.5k output per generation → Haiku 5.5 ≈ $0.0016, GPT-5 mini ≈ $0.006, Sonnet 5.5 ≈ $0.031. Assume 2-4 generations/user/month.
  - Net AI cost: roughly **$0.03-0.10/user/month** on small models, **$0.40-0.60/user/month** on Sonnet-class; use a cheap model for rerank and a stronger model only for CV writing.
- **Vector DB**: pgvector inside the primary Postgres (Supabase ships it) is sufficient to >1M job vectors; at 1,536 dims `halfvec` HNSW keeps index memory manageable; revisit Qdrant only if job volume exceeds a few million live vectors or p99 latency becomes a problem.

### Gaps

- Textkernel/Sovren parsing pricing; open-source bge/e5 benchmark comparisons for resume-job text; Cohere Rerank 3.5 pricing.

## Key Question 3: Skill taxonomy, skill-gap computation, course catalogs and affiliate revenue

### Takeaway
ESCO (free, EUPL/Apache-licensed API, downloadable as CSV/JSON-LD, v1.2.1 Dec 2025) is the safest taxonomy for a commercial product; Lightcast Open Skills (33k+ skills, 75k+ titles) is attractive but its free tier is for nonprofit/public-good use with commercial use requiring a license. Skill gap = (skills demanded by target-role postings or ESCO occupation profile) minus (skills extracted from CV), weighted by posting frequency. Coursera (up to 45% commission via Impact; Catalog API reportedly for approved affiliates only), Udemy (10% base, 7-day cookie, mobile-app sales excluded), edX (reported 4% via FlexOffers; Course Catalog API in beta requiring credentials) and Alison (Awin, 30-day cookie) offer affiliate revenue; ALX Africa is a free/scholarship route relevant to Nigeria but has no public API.

### Cited Findings

**Taxonomies**
- **Lightcast Open Skills**: free Skills and Titles APIs cover "every skill (33,000+) and job title (75,000+) in the Lightcast Open Skills Library" with names, IDs, types, categories, autocomplete, and "up to 50 skill extraction requests per month"; access-options page says free access is "available for nonprofit organizations and public-good initiatives, subject to approval" and "Commercial or production use requires a commercial license" (time-limited test access possible); refreshed monthly. [snippet] — [arXiv 2601.03558](https://arxiv.org/pdf/2601.03558)

**Skill-gap methods**
- Career-path paper (arXiv 2310.15636) maps résumé experience to ESCO occupations and scores each candidate occupation by the share of its linked (essential + optional) skills already present in the candidate's history. [snippet] — [arXiv 2310.15636](https://arxiv.org/pdf/2310.15636)

Not peer-reviewed. [snippet] — [preprints.org 202606.2015](https://www.preprints.org/manuscript/202606.2015)
- OECD presentation: word embeddings on online job postings estimate per-occupation skill relevance more granularly than frequency counts. [snippet] — [OECD/ESCO presentation (Manca)](https://esco.ec.europa.eu/system/files/2024-03/OECD%20presentation_FabioManca.pdf)

### Inferences
- Use ESCO as the skill ontology (free for commercial use), extract skills from both CVs and job descriptions with an embedding-based extractor (esco-skill-extractor approach, or an LLM structured-output call that must pick from ESCO labels), and compute per-target-role demand weights from your own ingested Nigerian postings (frequency of each ESCO skill in the last 90 days of postings for that title). Gap list = high-weight demanded skills absent from the CV; "CV is weak" when coverage of top-N demanded skills falls below a threshold (e.g., <50%).
- Map gap skills to courses by embedding course titles/descriptions into the same pgvector table (tagged `kind='course'`) and retrieving nearest courses, with an LLM assembling a 3-step learning path. Because catalog APIs are gated, start with manually curated/CSV catalogs (Coursera, Udemy, Alison, ALX, Google Africa) of the ~500 most relevant courses for Nigerian demand, with Impact/Awin affiliate deep links; request Coursera Catalog API access through Impact once approved.
- Revenue: Coursera (up to 45%) and Alison/Udemy are the realistic affiliate earners; ALX and free Google courses earn nothing but build trust and fit low-income users.

Email is the cheap primary channel: Amazon SES at ~$0.10 per 1,000 ($0.0001/email) or Resend (Free 3,000/mo; Pro $20 for 50,000; Scale $90 for 100,000) with Google/Yahoo bulk-sender compliance (SPF + DKIM + DMARC with alignment, RFC 8058 one-click unsubscribe honored within 2 days, spam-rate <0.3% and ideally <0.1%). ## Key Question 5: Lean stack recommendation (framework, auth, hosting, latency, mobile strategy)

### Inferences
- **Recommended lean stack**: Next.js (App Router, PWA manifest + service worker) on Vercel Pro ($20) or on a Hetzner VPS via Coolify (~€6-20) once Vercel usage bills grow; Supabase Pro ($25 + compute) in an EU region (Frankfurt/London; Cape Town if available) for Postgres + pgvector + Auth (Google sign-in) + Storage; Inngest free→$25 (or Trigger.dev, or pg-boss on the VPS) for nightly ingestion, embedding, matching and digest fan-out; Cloudflare in front for Lagos-edge caching of static assets.
- Python (FastAPI) is only needed if the team prefers Python ML tooling (sentence-transformers, pdfminer); otherwise keep a single TypeScript codebase and call hosted embeddings. A hybrid (Next.js front + small FastAPI worker on Hetzner for parsing/embedding) is reasonable and matches Resume Matcher's architecture.
- Auth: Supabase Auth (bundled, Google OAuth, phone OTP via Termii as custom SMS hook) — Clerk's per-MAU model is a poor fit for a low-ARPU Nigerian subscription.

## Key Question 6: Cost model at 1,000 / 10,000 / 100,000 users

### Takeaway
With cheap models for reranking and SES/Resend for email, variable cost is dominated by the job-data API and (if offered) WhatsApp — not by AI. Rough monthly totals: **~$150-250 at 1k users, ~$700-1,500 at 10k, ~$6k-15k at 100k** (without WhatsApp marketing sends; add ~$0.25-0.37/active user/month if weekly WhatsApp digests are included). **Per-user economics**: ≈ $0.10-0.30/registered user/month without WhatsApp; WhatsApp marketing adds ≈ $0.16/registered (≈ $0.27/active) user/month. **Cost-control levers**: embed once per job (content-hash keyed); rerank only top 30; prompt-cache the user profile and rubric; use Message Batches (50% off) for nightly rerank; cheaper model for rerank, stronger model only for CV writing; cap generations per plan; email first, WhatsApp as paid add-on or utility-only; negotiate a Jobberman/MyJobMag feed to replace per-query aggregator spend at scale.
