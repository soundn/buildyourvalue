## 1. CV ingestion: parsing PDF/DOCX/images into structured JSON

### Takeaway
In 2026 the pragmatic default is LLM-native parsing: send the PDF (or page images) to Claude with structured outputs (`output_config.format` + Zod via `client.messages.parse`) and emit a JSON Resume–shaped object; Claude's PDF path already renders every page as an image, so scanned CVs need no separate OCR step. Commercial parsers (Affinda, Textkernel/Sovren) remain viable but are opaque on price and sales-led; open-source parsers (OpenResume's pdf.js parser, Resume-Matcher) are useful as references or for ATS-readability checks, not as the primary extractor.

### Cited Findings
- Claude PDF support: "Maximum request size 32 MB", "Maximum pages per request 600 (100 when the request's context window is under 1M tokens)", standard PDF with no passwords/encryption. [fetched] — [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)
- How Claude processes PDFs: "The system converts each page of the document into an image. The text from each page is extracted and provided alongside each page's image." Documents are analysed as "a combination of text and images". [fetched] — [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)
- PDF token cost: "Each page typically uses 1,500–3,000 tokens per page depending on content density. Standard API pricing applies with no additional PDF fees"; image-token costs also apply per page because each page is converted to an image. [fetched] — [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)
- PDFs can be supplied three ways: base64, URL, or `file_id` from the Files API; the docs recommend the Files API "For PDFs you'll use repeatedly, or when you want to avoid encoding overhead". Document blocks support `cache_control` for prompt caching. [fetched] — [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)
- DOCX is not accepted as a document block: "Binary formats such as .xlsx or .docx are not supported in document blocks, so convert them to text or PDF first." Plain text (.txt/.csv/.md) can be uploaded to the Files API as `text/plain`. [fetched] — [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)
- Dense PDFs "can fill the context window before reaching the page limit"; the docs suggest splitting and "downsampling embedded images". [fetched] — [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)
- Structured outputs: pass `output_config.format` with `type: "json_schema"`; the TypeScript SDK offers `client.messages.parse()` with `zodOutputFormat(schema)` which "also validates the response", or `jsonSchemaOutputFormat` without Zod. Supported on Haiku 5.5, Sonnet 5.5, Opus 5.5 and others. Limits: no recursive schemas, no `minimum`/`maximum`/`minLength`/`maxLength`, `additionalProperties: false` required; complexity limits of 20 strict tools/request, 24 optional parameters, 16 union-typed parameters; compiled grammars cached 24h. "Changing `output_config.format` invalidates the prompt cache for that conversation thread." [fetched] — [Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- Structured outputs are incompatible with citations (`citations: {enabled: true}` with `output_config.format` returns a 400). [skill] — [Anthropic citations](https://platform.claude.com/docs/en/build-with-claude/citations)

No official 2026 price page found. [snippet] — [GetApp](https://www.getapp.com/all-software/a/resume-parser/); [FitGap](https://us.fitgap.com/products/affinda-resume-parser); [Capterra](https://www.capterra.com/p/212947/Resume-Parser/)

[snippet] — [JobsPipe Textkernel review](https://jobspipe.dev/blog/textkernel-review); [Capterra Sovren](https://www.capterra.com/p/33114/Resume-Parser/)
- OpenResume (xitanggg/open-resume): AGPL-3.0, 8.9k stars; builder + "resume parser" that "Helps users test and confirm how well an existing resume can be read by ATS software"; stack TypeScript/React/Next.js 13, PDF.js for reading PDFs, react-pdf for generating PDFs; claims "ATS friendly to top ATS platforms such as Greenhouse and Lever". [fetched] — [GitHub Resume-Matcher](https://github.com/srbhr/Resume-Matcher)

- FRESH résumé schema: an alternative open JSON/YAML format that "can be trivially converted to and from JSON Resume". [snippet] — [npm fresca](https://www.npmjs.com/package/fresca)

### Inferences
- **Recommended:** Claude-native parsing. Pipeline: (1) DOCX → PDF or text server-side (LibreOffice headless, or `mammoth` for text) because document blocks reject DOCX; (2) upload to the Files API once and reference by `file_id`; (3) `client.messages.parse()` with a Zod schema that mirrors JSON Resume (basics/work/education/skills/certificates/languages/projects) plus Nigerian-specific fields (NYSC status, state of origin optional, WAEC/NECO, HND/BSc/OND, professional bodies like ICAN/COREN/NIM); (4) store the raw JSON and a normalised copy. Scanned CVs work out of the box because each page is rasterised and sent to the vision path — a separate OCR stage is only needed for very low-quality phone photos, where a preprocessing step (deskew/contrast) before sending images helps.
- Cost per CV: a 2-page CV at ~2,000 text tokens/page plus image tokens is roughly 5–8k input tokens; on Haiku 5.5 ($0.10/MTok input) that is well under $0.001, on Sonnet 5.5 ($2/MTok) about $0.01–0.02. Use Sonnet 5.5 for parsing accuracy on messy layouts, Haiku 5.5 for re-parses/retries.
- Standards: adopt JSON Resume as the canonical internal schema (MIT, tooling, OSS importers in Reactive Resume) and expose import/export; HR Open is an enterprise/ATS-side standard without a usable open JSON resume spec, so treat it as a future integration target only.
- Commercial parsers (Affinda, Textkernel) are poor fits for a two-person team: sales-led pricing with ~$800+/month floors versus sub-cent LLM parsing; the only reason to add one is if an enterprise customer demands HR-XML/Textkernel-compatible output.

### Gaps
- Could not fetch Affinda's or Textkernel's official pricing pages; only third-party figures.
- No head-to-head accuracy benchmark (LLM parsing vs Affinda/Textkernel) found for 2025–2026.
- No published accuracy data for Claude PDF/vision on low-resolution phone photos of CVs, which is the common Nigerian case.

## 2. CV generation and tailoring: structured outputs, caching, batch, ATS-safe PDF/DOCX, Agent Skills, hallucination guardrails

### Takeaway
Generate tailored content as structured JSON (not free text), render it yourself to PDF (Playwright/Chromium or `@react-pdf/renderer`) and DOCX (`docx` npm, MIT) from one template model; this is cheaper, deterministic and more ATS-controllable than Anthropic's `docx`/`pdf` Agent Skills, which run in a code-execution container, are not ZDR-eligible and bill container time. Guard against fabricated achievements with provenance: every bullet must cite a source span in the user's master profile, enforced via schema plus a second verification pass.

### Cited Findings
- Agent Skills via Messages API: specify `container.skills` with `{type: "anthropic", skill_id: "docx" | "pdf" | "pptx" | "xlsx", version: "latest"}` plus the code execution tool; "Beta headers: the page doesn't mention any". Generated files come back as `file_id`s inside `bash_code_execution_tool_result` blocks and are downloaded via the Files API (`client.files.retrieve_metadata`, `client.files.download`). Up to 20 skills per request; multi-turn work reuses `container.id`. [fetched] — [Using Agent Skills with the API](https://platform.claude.com/docs/en/build-with-claude/skills-guide)
- Skills on the API "run in a sandboxed container with no network access and no runtime package installation"; "Agent Skills is not covered by ZDR arrangements." [fetched] — [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)
- Code execution billing: "Code execution is free when used with web search or web fetch"; otherwise billed by execution time, "Additional usage beyond 1,550 hours is billed at $0.05 USD per hour, per container", and "If files are included in the request, execution time is billed even if the tool is not called". [fetched] — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Code execution containers: "Container data retained up to 30 days"; ZDR eligible: No. [fetched] — [API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)
- `docx` (dolanmiu/docx): "Easily generate and modify .docx files with JS/TS with a nice declarative API", MIT, 6.0k stars, runs in Node and browsers; demos for tables, headers/footers, images, bullet points, HTML-to-document. [fetched] — [GitHub docx](https://github.com/dolanmiu/docx)
- npm naming: `react-pdf` "is a PDF viewer built on pdf.js"; `@react-pdf/renderer` "generates PDFs from React components". jsPDF is imperative and "less powerful for complex layouts". [snippet] — [pkgpulse react-pdf comparison](https://www.pkgpulse.com/guides/react-pdf-vs-react-pdf-renderer-vs-jspdf-pdf-in-react-2026)
- Typst is "a faster, more accessible alternative to LaTeX" that "compiles documents to PDF with fast incremental compilation"; Typst's own blog pitches server-side batch generation. [snippet] — [Typst blog: automated generation](https://typst.app/blog/2025/automated-generation)
- Resume-Matcher renders PDFs with "Headless Chromium via Playwright" and offers templates "single/two-column, Modern, LaTeX-style, Clean, Vivid, Deedy"; its ATS score is "plain code with no LLM call: keyword match (40%), skills coverage (20%), job-title match (15%), section completeness (15%), and date consistency (10%)". [fetched] — [GitHub Resume-Matcher](https://github.com/srbhr/Resume-Matcher)
- Reactive Resume: MIT, self-hostable (Docker), exports "PDF, JSON, DOCX", TypeScript + PostgreSQL; ~39.5k stars per one listing. [snippet] — [GitHub Reactive-Resume](https://github.com/AmruthPillai/Reactive-Resume); [rxresu.me docs](https://docs.rxresu.me/getting-started)
- Prompt caching economics: cache hit = 0.1x base input on most models, "0.05x on Claude Opus 5.5 and Claude Sonnet 5.5"; 5-minute write = 1.25x, 1-hour write = 2x; "caching pays off after one cache read for the 5-minute duration (1.25x write), or after two cache reads for the 1-hour duration (2x write)"; multipliers "stack with other pricing modifiers, including the Batch API discount". Max 4 cache breakpoints per request; minimum cacheable prefix is model-dependent (512–4096 tokens). [fetched] — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing); [skill] prompt-caching reference
- Batch API: "50 percent discount on both input and output tokens"; a batch "is limited to either 100,000 Message requests or 256 MB"; "most batches completing within 1 hour"; results "available for 29 days"; batches expire after 24 hours; `max_tokens: 0` pre-warming not allowed inside a batch. [fetched] — [Batch processing](https://platform.claude.com/docs/en/build-with-claude/batch-processing)
- Prefill is removed on current models (400 on Opus 5.5/Sonnet 5.5/Haiku 5.5); "Use structured outputs (`output_config.format`) or system prompt instructions to control response format instead." Forced `tool_choice: any/tool` also returns 400 on Opus 5.5/Sonnet 5.5. [skill] — [Anthropic migration guide](https://platform.claude.com/docs/en/about-claude/models/migration-guide)
- Fabrication research: a 2026 arXiv study of multi-stage LLM hiring pipelines found a fully automated baseline "invented candidate names, which appeared in 6 of 60 baseline outputs"; it frames a prompt instruction against unsupported facts as the cheapest mitigation and compares it to a human-in-the-loop checkpoint between stages. [snippet] — [arXiv 2608.26171](https://arxiv.org/pdf/2608.26171)
- "Resume Tailor" case study: a 12-node LangGraph pipeline with "provenance-aware fallback generation, anti-hallucination guardrails, and a conditional review loop", retrieving from a longitudinal career record rather than a single uploaded CV. [snippet] — [arXiv 2605.05257](https://arxiv.org/pdf/2605.05257)

[snippet] — [JobShinobi blog](https://jobshinobi.com/blog/free-resume-builder-ai-that-doesnt-add-fake-experience); [Indie Hackers post](https://www.indiehackers.com/post/i-built-an-honest-job-application-copilot-because-the-ai-resume-tools-all-either-lie-or-sound-like-robots-1391483a05)

### Inferences
- **Recommended generation path:** Sonnet 5.5 with `messages.parse()` producing a `TailoredResume` JSON (JSON Resume + `evidence[]` per bullet). System prompt + rubric + house style cached with a 1-hour TTL (users iterate over minutes); user master profile placed after the cache breakpoint. Use the Batch API for non-interactive work (nightly re-tailoring for saved jobs, bulk eval runs).
- **Recommended rendering path:** one HTML/React template → PDF via Playwright/Chromium (what Resume-Matcher does; simplest to keep ATS-safe: single column, real text layer, standard fonts, no tables for layout, no headers/footers for contact info) and → DOCX via `docx` (MIT) from the same JSON. `@react-pdf/renderer` is a reasonable alternative if you want to avoid a headless browser in serverless; Typst/LaTeX add a toolchain the team doesn't need. Anthropic's `docx`/`pdf` skills are better suited to ad-hoc agent outputs (e.g. the career-coach agent producing a one-off document) than to the core templated renderer, because they are non-deterministic, not ZDR-eligible, and add container cost/latency.
- **Hallucination guardrails (layered):** (1) schema-level `evidence: string[]` referencing master-profile item IDs, reject bullets with no evidence; (2) instruct "only use facts present in the profile; use `[ADD METRIC]` placeholders"; (3) a cheap Haiku 5.5 verification pass that classifies each bullet as supported/unsupported against the profile; (4) a UI diff highlighting new claims for the user to confirm before export. The arXiv fabrication paper supports keeping a human confirmation step between stages.

### Gaps
- No public ATS-parsing benchmark of Playwright-PDF vs react-pdf vs docx output; "ATS-safe" guidance is practitioner lore, not measured.
- Could not open the arXiv papers to read the quantitative results of prompt guardrails vs human checkpoints.
- Agent Skills guide pricing section was truncated; container billing is only known from the pricing page.

## 3. Matching: embeddings, pgvector, hybrid search, reranking, two-stage architecture, evaluation

### Takeaway
State of the art for a small team is a three-stage pipeline: hard SQL filters (location/salary/level) → pgvector HNSW recall on `halfvec` embeddings of normalised structured summaries (not raw text) fused with Postgres full-text via RRF → LLM rerank of the top ~30 with Claude producing a fit score and explanation in one structured call. Managed embedding APIs are all cheap ($0.02–$0.15/MTok); choose on quality for the job domain and ops simplicity, and evaluate with a small human-labelled nDCG set supplemented by LLM-as-judge.

### Cited Findings
- CareerBuilder production system: "fused embedding index built with Faiss for approximate nearest-neighbor search" then "a reranking model that uses additional contextual signals"; online A/B reported "roughly 104% higher click-through rate and about 37% higher nDCG over the baseline in a four-month online test". [snippet] — [arXiv 2107.00221](https://arxiv.org/pdf/2107.00221)
- JobsPipe (July 2026) describes job matching as "a three-stage pipeline of hard filters, vector recall, and a cross-encoder or LLM rerank", recommends "recomputing embeddings when postings change" and "normalizing resumes and job descriptions into structured summaries before embedding them". [snippet] — [JobsPipe AI job matching](https://jobspipe.dev/blog/ai-job-matching.md)
- TalentCLEF 2026 working notes: JobBERT as dense first-stage retriever; SPLADE and multilingual ColBERT as second-stage rerankers; "JobBERT plus SPLADE combination strongest on the development split". [snippet] — [CEUR-WS Vol-4283 paper484](https://ceur-ws.org/Vol-4283/paper484.pdf)
- pgvector v0.8.7: `halfvec` is 2 bytes/dimension, "Half vectors can have up to 16,000 dimensions", HNSW/IVFFlat index up to 4,000 dims (vs 2,000 for `vector`); `bit` type indexes up to 64,000 dims. Binary quantization example: `CREATE INDEX ON items USING hnsw ((binary_quantize(embedding)::bit(3)) bit_hamming_ops);` then rerank the top candidates by exact `<=>`. HNSW defaults `m=16`, `ef_construction=64`, `hnsw.ef_search=40`; "use the defaults unless seeing low recall". Iterative index scans since 0.8.0 (`SET hnsw.iterative_scan = relaxed_order;`, `hnsw.max_scan_tuples` default 20,000) fix the filtered-query under-fill problem. Hybrid search: "Use together with Postgres full-text search" and combine via "Reciprocal Rank Fusion or a cross-encoder". Tips: "Use the `halfvec` type instead of `vector` for a smaller working set", build indexes after loading, `CREATE INDEX CONCURRENTLY` in production. [fetched] — [GitHub pgvector](https://github.com/pgvector/pgvector)
- Neon benchmark (DBpedia 1M, 1536-d, HNSW m=32/ef_construction=256): halfvec gave ~50% storage saving, ~23% faster index build, 50% faster prewarm, "Equivalent query execution time and recall". [snippet] — [Neon: don't use vector, use halfvec](https://neon.com/blog/dont-use-vector-use-halvec-instead-and-save-50-of-your-storage-cost)
- pgvector 0.7.0 added parallel HNSW builds and scalar/binary quantization; AWS reports index builds "up to 67x faster versus 0.5.1" on Aurora. [snippet] — [AWS Database Blog](https://aws.amazon.com/blogs/database/load-vector-embeddings-up-to-67x-faster-with-pgvector-and-amazon-aurora)
- Embedding prices (all [snippet], vendor pages unreachable): OpenAI text-embedding-3-large ≈ $0.13/M input, batch $0.065/M (OpenAI staff-confirmed in forum) — [OpenAI community](https://community.openai.com/t/inconsistent-pricing-for-text-embedding-3-large-between-model-card-and-pricing-page/1338277); Cohere Embed v4 $0.12/M input (also $0.12 on Bedrock and OCI), 128k context, multimodal — [Maxim aggregator](https://www.getmaxim.ai/bifrost/model-library/compare/cohere/embed-v4.0.md); Google gemini-embedding-001 $0.15/M input, 2048-token input limit, Matryoshka dims down from 3072, free tier available — [Google Developers Blog](https://developers.googleblog.com/gemini-embedding-available-gemini-api/); Voyage voyage-4-lite $0.02/M, voyage-4 $0.06/M, voyage-4-large $0.12/M with 200M free tokens each, Batch API 33% discount (free credits don't apply to batch) — [markaicode](https://markaicode.com/pricing/voyage-ai-pricing); [usagepricing](https://usagepricing.com/blueprint/voyage-ai)
- Rerank prices [snippet]: Cohere Rerank 3.5 ≈ "$2.00 per 1k searches" where "1 search reranks up to 100 documents" (ceil(N/100) searches above that, ~500 tokens/doc); OpenRouter lists $0.001/search ($1/1k) — conflicting — [MemberJunction docs](https://docs.memberjunction.org/api/classes/_memberjunction_search-engine.CohereReRanker.html); [OpenRouter](https://openrouter.ai/cohere/rerank-v3.5). Voyage reranker cost = "(query tokens × number of documents) + total document tokens"; rerank-2.5 $0.05/M, rerank-2.5-lite $0.02/M, rerank-3 same, 200M free tokens — [Voyage docs](https://docs.voyageai.com/docs/pricing); [usagepricing](https://www.usagepricing.com/blueprint/activity/voyage-ai-2026-09-28-code-4-rerank-3-launch)
- Open-source embeddings: Qwen3-Embedding-8B "scored 70.58 on the MTEB Multilingual leaderboard as of mid-2025, ranking first", described as "the strongest open-source choice available under a commercially permissive license"; BGE-M3 called "the current open-weight production champion" for multilingual; NV-Embed-v2 72.3 on English MTEB (non-commercial licence). A practitioner notes the model that won on their data "was ranked 11th on the MTEB leaderboard at the time". [snippet] — [PremAI 2026 ranking](https://blog.premai.io/best-embedding-models-for-rag-2026-ranked-by-mteb-score-cost-and-self-hosting); [Tensoria guide](https://tensoria.fr/en/blog/embedding-models-2026-guide); [Towards AI](https://pub.towardsai.net/openais-embeddings-fell-to-13th-of-15-i-m-ditching-them-for-a-free-model-that-wins-by-11-points-f3290a7ee4cc)
- Claude structured outputs can return a typed fit-score object; strict tools up to 20 per request; grammar cached 24h. [fetched] — [Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- LLM-as-judge for relevance: in product search, LLM judges "agree with human evaluators between 85% and 89% of the time in nDCG@10, @5 and @1" and never flipped significant ranker comparisons — [arXiv 2406.00247](https://arxiv.org/pdf/2406.00247); item-level agreement is moderate but system rankings correlate ("Kendall's tau up to 0.92 for nDCG@100") — [alphaXiv 2511.23312](https://alphaxiv.org/abs/2511.23312v2); LLMs can fill unjudged "holes" in pooled collections — [arXiv 2405.04727](https://arxiv.org/html/2405.04727v1); multi-criteria rubrics (exactness, coverage, topicality, contextual fit) improve judge quality — [arXiv 2410.14044](https://arxiv.org/pdf/2410.14044.pdf); validate with Cohen's κ against a human subset — [arXiv 2504.12732](https://arxiv.org/pdf/2504.12732). All [snippet].

### Inferences
- **Recommended embeddings:** Voyage `voyage-4-lite` or `voyage-4` (cheapest managed, 200M free tokens covers a Nigerian-scale launch; Voyage is Anthropic's recommended embedding partner in its docs) or OpenAI text-embedding-3-large (ubiquitous, 3072-d with Matryoshka truncation to 1024). Avoid self-hosting Qwen3/BGE-M3 at this team size unless cost at scale forces it. Store as `halfvec(1024)` with HNSW (`m=16, ef_construction=64`), raise `ef_search` to 100 at query time, enable `hnsw.iterative_scan = relaxed_order` for filtered queries. Binary quantization is unnecessary below ~1M vectors.
- **What to embed:** not raw CV/JD text. Embed Claude-produced structured summaries ("role, seniority, top 15 skills, industry, location, must-haves") for both sides; keep separate embeddings for `skills_text` and `role_text` to allow weighted fusion. Re-embed on edit.
- **Hybrid:** combine pgvector cosine with `tsvector` BM25-style ranking via RRF in SQL; this catches exact Nigerian-specific terms (e.g. "NYSC", "ICAN", "Ikeja") that embeddings blur.
- **Rerank:** for 30 candidates, a single Claude call that scores all 30 jobs in one structured response is cheaper and more useful than Cohere/Voyage rerank because it also yields the explanation and skill-gap list the product needs; Cohere Rerank (~$0.002/search of 100 docs) is a good intermediate stage if recall is widened to 200–500 before the LLM.
- **Evaluation:** build a 200–500 pair labelled set (3-level graded relevance) from Nigerian JDs + anonymised profiles; compute nDCG@10 and Recall@50 per stage; use Sonnet 5.5 as a multi-criteria judge to extend labels, validated by κ against the human subset. Keep this eval in CI for prompt/embedding changes.

### Gaps
- No official pricing pages for OpenAI, Cohere, Voyage or Google were fetchable; all prices are [snippet] with some conflicts (Cohere rerank $1 vs $2 per 1k).
- No independent 2025–2026 benchmark of binary-quantized HNSW recall on pgvector.
- No published benchmark of LLM rerankers specifically for job↔candidate matching beyond TalentCLEF (not opened).

## 4. Skills taxonomy and gap analysis: ESCO, Lightcast, O*NET, open-source extractors, "fit lift"

### Takeaway
ESCO (free, downloadable CSV/JSON-LD, EU reuse policy permits commercial use with attribution) is the right backbone taxonomy; O*NET is free for occupation descriptors with attribution and rate limits; Lightcast Open Skills requires a commercial licence for production. Do skill extraction with Claude structured outputs constrained to ESCO IDs (via embedding lookup of ESCO skill labels in pgvector) rather than running spaCy-based extractors; present "fit lift" as a measured delta on your own scoring function with explicit uncertainty, not as a probability of being hired.

### Cited Findings
- ESCO 1.2.1 (December 2025) is a minor quality update; the classification is downloadable in "CSV, JSON-LD, ODS, RDF, TTL, and XML" and via the ESCO API; a delta file lists changed concepts. The ESCO API software is EUPL 1.2. ## 6. Scam and fraud detection on listings

### Takeaway
Combine deterministic rules (fee requests, Gmail/Yahoo contact domains, SMS-only contact, salary outliers, urgency) with a Haiku 5.5 structured classifier returning a risk score plus reasons, and enrich with domain checks (MX/RDAP age, free/disposable provider lists) and Nigerian employer verification via a CAC lookup API (Dojah; no official CAC API exists). Use EMSCAD (17,880 postings, 866 fraudulent) to bootstrap and sanity-check, but build a Nigerian-labelled set because EMSCAD is 2014-era and Western.

### Cited Findings
- EMSCAD: "17,880 real-life job postings in which 17,014 are real and 866 are fake", from the University of the Aegean; Kaggle mirror "Real or Fake: Fake JobPosting Prediction" (17,880 rows, 18 columns incl. `fraudulent`). Papers report XGBoost 96.8% accuracy and ~98% on this imbalanced set. [snippet] — [Analytics India Mag](https://analyticsindiamag.com/classifying-fake-and-real-job-advertisements-using-machine-learning/); [Kaggle dataset via Baselight](https://baselight.app/u/kaggle/dataset/shivamb_real_or_fake_fake_jobposting_prediction)
- Fraud-BERT (2025): fine-tuned BERT on an imbalanced posting dataset, F1 0.93, 99% accuracy. [snippet] — [Springer 10.1007/s10791-025-09502-8](https://link.springer.com/article/10.1007/s10791-025-09502-8)
- Hybrid rules + local LLM (IJERT 2025): "heuristic engine scores postings on a 100-point risk scale across 15+ rules", then an LLM (Phi-3/Mistral) outputs REAL/SUSPICIOUS/FAKE with confidence; evaluated on data-entry scams, mystery-shopper fraud and MLM schemes. [snippet] — [IJERT hybrid approach](https://www.ijert.org/fake-job-posting-detection-using-open-source-large-language-models-with-heuristic-pre-screening-a-hybrid-approach-ijertv15is031714)
- Nigerian red flags: fees "for processing, training, onboarding, or medical tests – ranging from ₦5,000 to ₦500,000" — [BusinessDay](https://businessday.ng/opinion/article/the-rise-of-recruitment-fraud-in-nigeria-how-job-seekers-can-stay-safe/); government agencies "always use official means of communication, not public email systems such as Gmail, Yahoo Mail and Hotmail" and federal applications run through portals — [AllAfrica/Africa Check](https://allafrica.com/stories/202410010381.html); SMS-only interview invitations are "most likely a fake job or scam job" — [Jobberman](https://www.jobberman.com/discover/identify-job-scams); MLM "job vacancies" that exist to charge a joining fee; impersonation of known firms and "government slots"; fake AI-generated offer letters (FAAN Aug 2026, NUPRC, Nigeria Customs Oct 2025) — [MSME Africa](https://msmeafricaonline.com/faan-denies-ongoing-recruitment-warns-job-seekers-against-fake-employment-letters/). All [snippet].
- CAC verification: no official CAC API found; the public portal supports manual search by name or RC number — [Youverify](https://youverify.co/blog/how-to-check-if-a-company-is-registered-in-nigeria); Dojah's CAC Lookup API (`/api/v1/kyc/cac/basic`, app-ID header) returns business name, RC number, company type, registration date, status, registered address; an advanced tier adds directors/shareholders — [Dojah docs](https://docs.dojah.io/overview/business-verification/cac); Apify scrapers exist but return no directors/addresses and warn that CAC name search is a word-level similarity search producing many false matches — [Apify CAC lookup](https://apify.com/mansalabs/cac-company-lookup). All [snippet].
- Email/domain checks: an MX record shows a domain accepts mail; absence of MX with an A record may still accept mail; disposable-domain lists and free-provider flags (Gmail/Outlook) are standard; SMTP mailbox probing is unreliable and often treated as abuse; one tool scores syntax 30 + live MX 40 + not-disposable 20 + not-role 10. Domain-age checks exist but the method (WHOIS/RDAP) wasn't documented. [snippet] — [Apify email-verifier-dns](https://apify.com/axery/email-verifier-dns.md); [Apify catalyst email verifier](https://apify.com/catalyst_prime/email-verifier.md)
- Claude Haiku 5.5 pricing $0.10/$0.50 per MTok (batch $0.05/$0.25). [fetched] — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)

### Inferences
- **Recommended architecture:** (1) deterministic rule engine in TypeScript producing a 0–100 risk score with named rules (fee/payment words incl. "processing fee", "training fee", "guarantor fee"; WhatsApp/Telegram-only contact; free-mail contact for a claimed corporate; SMS-only; salary > 2x the role median; vague requirements + "urgent"; "government slot"); (2) Haiku 5.5 structured classification (`risk: low|medium|high`, `signals[]`, `rationale`) with the rule output as context — at ~1.5k tokens per listing this is ≈$0.0002/listing, or half via Batch; (3) enrichment: Node `dns.resolveMx`, RDAP lookup for domain creation date, disposable/free-provider lists, logo similarity (perceptual hash or embedding) against a known-brand table to detect impersonation; (4) employer verification tier: Dojah CAC lookup by RC number or name, cached, with a "verified employer" badge only when CAC status is active and the contact domain matches the employer's web domain.
- Run EMSCAD as a regression test for the rules+LLM classifier (precision/recall on the 866 fraudulent rows) but label 300–500 Nigerian listings (Jobberman/LinkedIn/WhatsApp forwards) since Nigerian scam patterns (fees in naira, NYSC-targeted offers, fake government recruitment letters) are absent from EMSCAD.
- Fake-offer-letter detection is a separate user-facing feature: let users upload an offer letter; Claude vision checks letterhead/domain/CAC consistency and known-agency "we are not recruiting" notices.

## 9. Anthropic-specific: Claude Agent SDK vs Managed Agents vs Tool Runner for an "apply assistant" / "career coach"; MCP; structured outputs; citations; current recommendations

### Takeaway
For a two-person TypeScript team, build the career-coach as a plain Claude API tool-use agent (SDK beta Tool Runner with `betaZodTool`) inside your own Node backend — your tools are already Postgres queries and internal services; reserve Managed Agents ($0.08/session-hour + tokens) for long-running, sandboxed tasks such as an autonomous apply assistant that must browse/fill forms, and skip the Claude Agent SDK (a Claude Code harness aimed at coding/filesystem agents).
