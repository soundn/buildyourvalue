## Key Question 1: Claude Code project setup (CLAUDE.md, hooks, permissions, subagents/skills, plugin evals, GitHub Action, cloud sessions, cost control)

### Takeaway
Keep a short root `CLAUDE.md` (<200 lines) plus path-scoped `.claude/rules/*.md` per workspace package; enforce typecheck/lint/test with a `PostToolUse` hook on `Edit|Write` that exits 2 on failure; commit `.claude/settings.json` with `Bash(npm run *)`-style allow rules and `.env` deny rules; move repeated procedures ("add an endpoint") into project skills and use subagents only for verbose/isolated work; use the Claude Code GitHub Action (`@v1`) for PR review on your own CI with a subscription OAuth token or API key; expect ~$13/active day per developer on API billing, or a Pro/Max subscription per person.

### Cited Findings

**CLAUDE.md and rules**
- CLAUDE.md should hold "facts Claude should hold in every session: build commands, conventions, project layout, 'always do X' rules"; multi-step procedures or part-of-codebase instructions belong in a skill or a path-scoped rule. Target "under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." `[fetched]` — [Claude Code docs: memory](https://code.claude.com/docs/en/memory)
- Monorepo behaviour: "CLAUDE.md and CLAUDE.local.md files in the directory hierarchy above the working directory are loaded at launch. Files in subdirectories load on demand" — each subdirectory CLAUDE.md loads "once Claude reads, writes, or edits another file in that subdirectory." `claudeMdExcludes` skips irrelevant files in large monorepos. `[fetched]` — [memory docs](https://code.claude.com/docs/en/memory)
- `.claude/rules/*.md` files are discovered recursively; a rule with a `paths:` frontmatter list loads only when Claude works with matching files, "reducing noise and saving context space". Each brace-expanded `paths` list is capped at 1,000 patterns / 4 MiB. `[fetched]` — [memory docs](https://code.claude.com/docs/en/memory)
- `/init` generates a starting CLAUDE.md and "suggests improvements rather than overwriting" an existing one; `CLAUDE_CODE_NEW_INIT=1` makes `/init` ask which artifacts to set up (CLAUDE.md, skills, hooks). `/doctor prompt-audit` finds contradictions across CLAUDE.md, rules, skills and agents. `[fetched]` — [memory docs](https://code.claude.com/docs/en/memory)
- Claude Code (v2.1.277+) reads `AGENTS.md` when no CLAUDE.md exists, so one instruction file can serve other coding agents too. `[fetched]` — [memory docs](https://code.claude.com/docs/en/memory)
- CLAUDE.md and auto memory are "context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead." `[fetched]` — [memory docs](https://code.claude.com/docs/en/memory)
- Auto memory (notes Claude writes itself) loads "first 200 lines or 25KB" every session, per repository. `[fetched]` — [memory docs](https://code.claude.com/docs/en/memory)

**Hooks**
- Hook events include `SessionStart`, `SessionEnd`, `Setup`, `UserPromptSubmit`, `Stop`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `SubagentStart/Stop`, `PreCompact/PostCompact`, `ConfigChange`, `FileChanged`, `WorktreeCreate`, among others. Handler types: `command`, `http`, `mcp_tool`, `prompt`, `agent`. `[fetched]` — [Claude Code hooks reference](https://code.claude.com/docs/en/hooks)
- Exit code semantics: exit 0 = success (stdout parsed as JSON if a single object); exit 2 = blocking error, "stderr is the reason fed back to Claude"; any other code is non-blocking. "Exit 1 is not a block, so use exit 2 for policy enforcement." `[fetched]` — [hooks reference](https://code.claude.com/docs/en/hooks)
- Hooks are "fail-open by default. If a hook crashes or times out, the action usually proceeds. Set `"onFailure": "block"` (v2.1.295+) to block on failure." Default timeout 600s for command hooks; 30s on `UserPromptSubmit`. `[fetched]` — [hooks reference](https://code.claude.com/docs/en/hooks)
- The docs' canonical example for this exact use case: a `PostToolUse` hook matching `Write|Edit` that runs `${CLAUDE_PROJECT_DIR}/.claude/hooks/check-ts.sh`, which runs `npx eslint "$file" && npx tsc --noEmit`, pipes the first 50 lines of errors to stderr and exits 2. A handler-level `"if": "Edit(*.ts)"` filter is supported. `[fetched]` — [hooks reference](https://code.claude.com/docs/en/hooks)
- Hooks in project settings follow the workspace trust rule; "Hooks run arbitrary commands with your user privileges. Review any hook you didn't write, especially from plugins." `additionalContext` injected text is capped at 10,000 characters. `[fetched]` — [hooks reference](https://code.claude.com/docs/en/hooks)
- Cost docs show a `PreToolUse` hook on `Bash` that rewrites `npm test` to `... | grep -A 5 -E '(FAIL|ERROR|error:)' | head -100` via `hookSpecificOutput.updatedInput`, cutting test output from "tens of thousands of tokens to hundreds." `[fetched]` — [Manage costs](https://code.claude.com/docs/en/costs)

**Permissions and settings**
- Settings scopes: `~/.claude/settings.json` (user), `.claude/settings.json` (shared project, commit it: "Team permissions, hooks, plugins, and the environment variables the project needs"), `.claude/settings.local.json` (personal, gitignored), managed. Precedence: managed > `--settings` > project local > shared project > user; list keys like `permissions.allow` merge across files. `[fetched]` — [Settings files and precedence](https://code.claude.com/docs/en/settings)
- Rules evaluate "deny, then ask, then allow. The first match in that order determines the outcome"; an allow rule can't carve an exception out of a deny rule. `[fetched]` — [Configure permissions](https://code.claude.com/docs/en/permissions)
- Bash prefix rules: `Bash(npm run *)` matches `npm run build`, `npm run test --watch` and bare `npm run`, not `npm install`; `:*` is an equivalent trailing wildcard. Claude Code is shell-operator aware (`&&`, `||`, `;`, `|`), so `Bash(safe-cmd *)` does not approve `safe-cmd && other-cmd`. `npx`, `docker exec` and similar runners are NOT stripped, so `Bash(npm *)` doesn't cover `npx`. `[fetched]` — [permissions](https://code.claude.com/docs/en/permissions)
- Secret protection: `Read(./.env)`, `Read(./.env.*)`, `Read(./secrets/**)` deny rules; `Read(//**/.env)` for anywhere on disk. Only `Edit(path)` and `Read(path)` rules match; `Write(path)` rules "never match". `[fetched]` — [permissions](https://code.claude.com/docs/en/permissions); [settings example](https://code.claude.com/docs/en/settings)
- Argument-constraining Bash patterns "are fragile" (e.g. `Bash(curl http://github.com/ *)`); the recommended pattern is deny `curl`/`wget` and allow `WebFetch(domain:github.com)` instead. `[fetched]` — [permissions](https://code.claude.com/docs/en/permissions)
- MCP permission rules: `mcp__<server>__<tool>`; allow-rule globs only after a literal `mcp__<server>__` prefix (e.g. `mcp__github__*`); deny `"mcp__*"` removes all MCP tools. `[fetched]` — [permissions](https://code.claude.com/docs/en/permissions)
- `permissions.defaultMode` values `auto` and `bypassPermissions` "don't take effect from project or local settings; set them in user or managed settings instead" (v2.1.257+). Committed `permissions.allow` rules, `additionalDirectories`, `extraKnownMarketplaces` and most `env` apply only after each teammate trusts the folder; `deny`/`ask` apply immediately. `[fetched]` — [settings](https://code.claude.com/docs/en/settings)
- Auto mode: "A separate classifier model reviews actions instead of you and blocks the ones it judges unsafe"; it is the default starting mode for interactive terminal/VS Code sessions. Manual mode starts read-only and asks before edits/commands. `[fetched]` — [Security](https://code.claude.com/docs/en/security)
- A published JSON schema (`https://json.schemastore.org/claude-code-settings.json`) gives editor autocomplete for settings files. `[fetched]` — [settings](https://code.claude.com/docs/en/settings)

**Skills, subagents, commands**
- A skill is a directory with `SKILL.md` (YAML frontmatter + Markdown); "Unlike CLAUDE.md, a skill's body loads only when used." Project skills live in `.claude/skills/<name>/SKILL.md`; nested `<subdir>/.claude/skills/` apply to sessions in or below that subdirectory. Custom slash commands have been merged into skills (`.claude/commands/deploy.md` and `.claude/skills/deploy/SKILL.md` both create `/deploy`). `[fetched]` — [Skills](https://code.claude.com/docs/en/skills)
- Frontmatter controls: `disable-model-invocation: true` (only humans can run it, "useful for deploys or commits"), `user-invocable: false`, `allowed-tools`, `context: fork` + `agent` (run in a subagent), `paths`, `hooks`, `model`, `effort`. Dynamic context injection with `` !`git diff HEAD` `` runs a command before Claude sees the skill. `[fetched]` — [Skills](https://code.claude.com/docs/en/skills)
- `/skill-doctor` (v2.1.252+) "reports what each skill costs in context and how often it's used, flags skills that have never been invoked". The `skill-creator` plugin (`/plugin install skill-creator@claude-plugins-official`) stores test prompts in `evals/evals.json`, runs each in an isolated subagent and grades results. `[fetched]` — [Skills](https://code.claude.com/docs/en/skills). A separate community plugin also named "skill-doctor" exists (JoaquinCampo) `[snippet]` — [claudepluginhub](https://www.claudepluginhub.com/plugins/joaquincampo-skill-doctor)
- Subagents: Markdown files in `.claude/agents/` with `name`, `description`, `tools`, `model` (`sonnet`/`opus`/`haiku`/`inherit`), `permissionMode`, `skills`, `hooks`, `mcpServers`, `maxTurns`, `isolation` (git worktree). Built-ins: Explore (read-only), Plan, general-purpose. "Subagent requests count toward the same usage limits as your main conversation, so isolation saves context but not cost." Startup warning when custom subagent descriptions exceed 15,000 tokens. `[fetched]` — [Subagents](https://code.claude.com/docs/en/sub-agents)
- When to use which: subagent "when a task produces verbose output you don't need in the main context, when you need enforced tool restrictions, or when the work is self-contained"; skill "for reusable prompts or workflows that should run in the main conversation's context". `[fetched]` — [Subagents](https://code.claude.com/docs/en/sub-agents)

**Plugins and `claude plugin eval`**
- A plugin bundles skills, agents, hooks, MCP servers (and optionally a JS "mod"). "An enabled plugin is part of every session": each invocable skill/agent's name+description sits in context every turn. Official marketplace plugins show a "Context cost" estimate before install; `claude plugin disable` turns one off without uninstalling. `[fetched]` — [Plugins overview](https://code.claude.com/docs/en/plugins)
- `claude plugin eval` (requires v2.1.269+) runs a plugin against prompt+grader cases; `claude plugin eval init` has Claude propose the cases. Each case runs 3 times with the plugin and 3 without (with-arm vs no-plugin baseline), reporting `WITH`, `W/OUT`, `Δ` and list-price `COST`. "Every eval run and every judge grader is a real model call on your account". `--ablation none` halves cost; `--threshold` gates CI; pin `--model` in CI "so a model rollout isn't mistaken for a plugin regression". Grader types: `regex`, `tool_used`, `tool_order`, `file_exists`, `llm`, `baseline`; no custom-code graders. `claude plugin validate` checks files for syntax/schema only. `[fetched]` — [Test plugins with evals](https://code.claude.com/docs/en/plugin-evals)
- Plugin trust: "A Claude Code plugin you install can execute arbitrary code on your machine with your user privileges"; hooks, monitors, MCP/LSP servers and mods run outside the sandbox and outside permission rules; `bin/` is added to Bash PATH; auto-update can change reviewed files. Review `hooks/hooks.json`, `.mcp.json`, `bin/` and run `claude --plugin-dir <dir> plugin details <name>`. Official marketplace names (`claude-plugins-official`, `anthropic-agent-skills`, `knowledge-work-plugins`, etc.) are only accepted from `github.com/anthropics/`. `[fetched]` — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security)

**GitHub Action, Code Review, cloud sessions**
- `anthropics/claude-code-action@v1`: interactive mode (responds to `@claude` mentions) when no `prompt`; automation mode when `prompt` is given. Setup via `/install-github-app` (needs `gh` and repo admin). Auth secret is either `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`, "available on Pro, Max, Team, and Enterprise plans"); "If you authenticate with an OAuth token, runs use your Claude subscription instead of API billing." `[fetched]` — [Claude Code GitHub Actions](https://code.claude.com/docs/en/github-actions)
- The documented PR-review workflow installs `code-review@claude-code-plugins` via `plugin_marketplaces`/`plugins` and runs `/code-review:code-review --comment ...` with `claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'`; Claude skips drafts, trivial PRs and PRs it already commented on. Fork PRs don't get secrets on public repos. `[fetched]` — [GitHub Actions docs](https://code.claude.com/docs/en/github-actions)
- Cost levers for the Action: `--max-turns`, workflow timeouts, concurrency controls, concise CLAUDE.md; costs are GitHub Actions minutes plus API tokens (or subscription usage). `[fetched]` — [GitHub Actions docs](https://code.claude.com/docs/en/github-actions)
- Action security: only users with write access trigger runs; bots blocked unless `allowed_bots`; `allowed_non_write_users` is "high risk"; the GitHub App gets a short-lived repo-scoped token; never use a PAT ("could be recovered over time through prompt injection"); hidden-text injection in PR/issue bodies is stripped "but bypasses may exist"; config files (`.claude/`, `.mcp.json`, `CLAUDE.md`, `.husky/`) are restored from the base branch, but `package.json`/lockfiles are not, so hooks that run package scripts "can therefore execute PR-supplied code" — invoke pinned tools directly (`bunx prettier@3.5.3 --no-config`). By default Claude commits to a branch and links to create a PR; no automatic PRs. `[fetched]` — [claude-code-action security.md](https://github.com/anthropics/claude-code-action/blob/main/docs/security.md)
- Hosted "Code Review" (no workflow file) is **Team and Enterprise only**, runs on Anthropic infrastructure, posts inline comments and a check run, never approves/blocks, and is "billed on token usage through usage credits, separately from your plan's included usage"; no flat per-review price; Quick/Standard/Deep levels; monthly spend limit per org. On any plan you can instead run `/code-review` locally. `[fetched]` — [Code Review](https://code.claude.com/docs/en/code-review); [Code Review costs](https://code.claude.com/docs/en/code-review-costs)
- Cloud sessions (claude.ai/code, `claude --cloud "task"`, mobile) are "available on Pro, Max, and Team plans"; they "count toward your plan's usage limits ... and there's no separate charge for the cloud VM". GitHub credentials "never enter a session's VM" (proxy attaches them). Auto-fix PRs: Claude watches a PR for CI failures/review comments and pushes fixes; requires the Claude GitHub App; warning that Claude's replies can trigger comment-triggered automation (Atlantis etc.). `--teleport` pulls a cloud session into the terminal. `[fetched]` — [Claude Code in the cloud](https://code.claude.com/docs/en/claude-code-on-the-web)
- Cloud environments: network access levels None / Trusted (allowlisted registries, GitHub, cloud SDKs) / Full / Custom; "network secrets" are API keys stored on the environment that "Anthropic's agent proxy adds ... to requests for the hosts you list, after each request leaves the session's VM, so the key itself stays outside the VM"; environment variables are readable by anyone using the environment, so secrets should be network secrets instead. Cloud sessions don't load local plugins or user settings. `[fetched]` — [Configure cloud environments](https://code.claude.com/docs/en/cloud-environments); [settings](https://code.claude.com/docs/en/settings)
- Cloud session SessionStart hooks: the `session-start-hook` skill in this team's session exists to create SessionStart hooks so cloud sessions can run tests and linters (from the session skill listing).

**Cost control**
- "Across enterprise deployments, the average cost is around $13 per developer per active day and $150-250 per developer per month, with costs remaining below $30 per active day for 90% of users." `[fetched]` — [Manage costs](https://code.claude.com/docs/en/costs)
- Levers: `/clear` between unrelated tasks; Sonnet for most work, Opus for architecture; `model: haiku` for simple subagents; MCP tool definitions are deferred by default (tool search) but CLI tools like `gh`, `sentry-cli` are still cheaper than MCP servers; disable unused MCP servers via `/mcp`; keep CLAUDE.md under 200 lines and move workflows to skills; lower `/effort`; `MAX_THINKING_TOKENS` on fixed-budget models (adaptive models ignore it; "You can't turn off thinking on Opus 5.5, Sonnet 5.5, Haiku 5.5, or the Fable models"); agent teams use ~7x tokens. `/usage` shows per-skill/subagent/plugin/MCP attribution and recommendations; `/insights` writes an HTML usage report. `[fetched]` — [Manage costs](https://code.claude.com/docs/en/costs)
- Console (API) orgs get an auto-created "Claude Code" workspace with its own spend limits; OpenTelemetry export works on every setup for per-user metrics. Rate-limit recommendation for 1-5 users: 200k-300k TPM and 5-7 RPM per user. `[fetched]` — [Manage costs](https://code.claude.com/docs/en/costs)

### Inferences
- A concrete minimum for this repo: root `CLAUDE.md` (~100 lines: workspace layout, `npm run` commands, "use Zod schemas from `packages/core`", migration workflow) + `.claude/rules/api.md` (paths: `apps/api/**`), `.claude/rules/web.md` (paths: `apps/web/**`, `apps/admin/**`), `.claude/rules/db.md` (paths: `supabase/**`). Per-package `CLAUDE.md` files are an alternative but rules give explicit path scoping and one place to audit.
- Hook set that pays off immediately: (1) `PostToolUse` on `Edit|Write` running Biome/ESLint on the file and `tsc -b --noEmit`-equivalent for the touched package, exit 2 on failure (per docs example); (2) `PreToolUse` on `Bash` filtering `vitest`/`npm test` output to failures; (3) `SessionStart` to `npm ci` in cloud sessions. Do not rely on hooks for hard blocks unless `onFailure: block` is set, and use `permissions.deny` for genuine policy.
- Permission allowlist to commit: `Bash(npm run *)`, `Bash(npx vitest *)`, `Bash(npx tsc *)`, `Bash(npx biome *)`, `Bash(git status)`, `Bash(git diff *)`, `Bash(gh pr view *)`, `Bash(supabase db diff *)`; deny: `Read(./.env)`, `Read(./.env.*)`, `Read(./supabase/.temp/**)`, `Bash(git push --force *)`, `Bash(supabase db reset *)` in prod contexts, `Bash(curl *)`/`Bash(wget *)` in favour of `WebFetch(domain:...)`. Because `npx` isn't stripped, list `npx` commands explicitly.
- Skills to write first (each is a repeated multi-step procedure, so it belongs in a skill not CLAUDE.md): `/add-endpoint` (Zod schema in core → Hono route with `@hono/zod-openapi` → Vitest test → regenerate OpenAPI/Scalar docs), `/new-migration` (Supabase migration + RLS policy checklist + `supabase db diff` + typegen), `/email-template` (React Email/Resend template + preview + test send to sandbox). Mark `/release` and `/deploy` with `disable-model-invocation: true`. Use `skill-creator` evals to check the description triggers, and `/skill-doctor` monthly to prune.
- For a 2-person team, the Team plan's hosted Code Review is attractive only if you're already paying for Team seats; on Pro/Max the GitHub Action review workflow with `CLAUDE_CODE_OAUTH_TOKEN` costs nothing beyond plan usage, which is the cheapest PR-review path.
- Budget: two Max 5x seats ($200/mo) or Team Premium seats (~$200-250/mo) is in line with the $150-250/dev/month API average and avoids per-token anxiety; the subscription OAuth token also covers the GitHub Action.

### Gaps
- No official benchmark on how much `.claude/rules` path scoping saves versus nested CLAUDE.md files.
- The hooks page was 280k characters; only the first 100k was read, so any newer hook events or fields beyond those listed were not verified.
- Whether `/skill-doctor` is a bundled command or community plugin: the official skills page says `/skill-doctor` is built in (v2.1.252+); a same-named community plugin also exists. Treat the built-in as authoritative.

## Key Question 2: MCP servers worth connecting (Supabase, Vercel, Sentry, PostHog, Resend, GitHub, Playwright, Linear, Context7, Paystack, Cloudflare)

### Takeaway
Connect, interactively only: Supabase (hosted, `read_only=true` + `project_ref` scoped to a dev/branch project), Sentry, PostHog (feature-filtered), Playwright (headless, origin-restricted), Context7 (docs), and Vercel if you deploy there; keep GitHub on the `gh` CLI; use Resend MCP only against a sandbox domain; Paystack's official MCP is test-key-only by design (good); skip Linear unless you adopt Linear, and skip Cloudflare unless you use Workers. Nothing with write access to production data belongs in CI.

### Cited Findings

**Claude Code MCP mechanics (applies to all)**
- Add remote servers with `claude mcp add --transport http <name> <url>`; OAuth via `/mcp`. Scopes: local (default, `~/.claude.json`), project (`.mcp.json`, committed, prompts for approval), user. `${VAR}` expansion works in `.mcp.json`; some credential variables (e.g. `ANTHROPIC_API_KEY`) deliberately read as empty "so a project can't send your credentials to a server it names". `[fetched]` — [Connect Claude Code to MCP servers](https://code.claude.com/docs/en/mcp)
- "In `claude -p` runs and Agent SDK sessions, the prompt can't appear, so project servers load without asking" — block with `disabledMcpjsonServers`. MCP output is limited to 25,000 tokens by default (`MAX_MCP_OUTPUT_TOKENS`). Tool search defers tool definitions until used. `[fetched]` — [MCP docs](https://code.claude.com/docs/en/mcp)
- "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk." Anthropic "reviews connectors against its listing criteria ... but does not security-audit or manage any MCP server." `[fetched]` — [MCP docs](https://code.claude.com/docs/en/mcp); [Security](https://code.claude.com/docs/en/security)
- Prefer CLI tools where they exist: "Tools like gh, aws, gcloud, and sentry-cli are still more context-efficient than MCP servers because they don't add any per-tool listing." `[fetched]` — [Manage costs](https://code.claude.com/docs/en/costs)

**Supabase MCP**
- Hosted server `https://mcp.supabase.com/mcp`, OAuth 2.1 login; URL parameters `read_only=true` (excludes mutating tools), `project_ref=<ref>` (drops `project_id` from tool inputs and excludes account-level tools), `features=database,docs` to restrict feature groups. Local CLI server at `http://localhost:54321/mcp` has a limited tool subset and no OAuth. The README points to supabase.com/docs security best practices ("Security risks") but does not reproduce them. `[fetched]` — [supabase-community/supabase-mcp README](https://github.com/supabase-community/supabase-mcp)
- The official Supabase Claude Code plugin bundles the remote MCP server plus two skills (`supabase`, `supabase-postgres-best-practices`) and an `agents/` directory; first MCP use opens a browser login; "If you already added the Supabase MCP server manually, remove it after installing the plugin so the same tools don't load twice." Skills are synced from `supabase/agent-skills`. `[fetched]` — [supabase-community/supabase-plugin](https://github.com/supabase-community/supabase-plugin)
- `supabase/agent-skills` (MIT): the `supabase` skill covers Database, Auth, Edge Functions, Realtime, Storage, SSR (`@supabase/ssr` for Next.js), "auth troubleshooting (sessions, JWTs, cookies, RLS)", migrations and security audits; `supabase-postgres-best-practices` has eight prioritized categories including "Security & RLS (Critical)". Install: `claude plugin marketplace add supabase/agent-skills` then `claude plugin install supabase@supabase-agent-skills`. `[fetched]` — [supabase/agent-skills](https://github.com/supabase/agent-skills)
- The Supabase MCP security guidance page (prompt injection via data, don't connect to production, read-only, branching) could not be fetched (supabase.com DNS-blocked; raw GitHub path 404). The README's existence of a dedicated "Security risks" section is confirmed `[fetched]`, its content is not.

**Vercel MCP** `[snippet]`
- Hosted at `https://mcp.vercel.com`, OAuth; Claude Code setup `claude mcp add --transport http vercel https://mcp.vercel.com` then `/mcp`; tools cover "documentation search, project and deployment management, deployment log analysis, and Web Analytics queries", split into public (unauthenticated) and authenticated tools; "Vercel MCP only supports AI clients that have been reviewed and approved by Vercel." — [Vercel MCP docs via search](https://vercel.com/docs/mcp/vercel-mcp)
- A "Vercel" plugin ("Manages deployments, builds, logs, and domains") is listed in Anthropic's official marketplace. `[fetched]` — [claude.com/marketplace/plugins](https://claude.com/marketplace/plugins)

**Sentry MCP**
- Hosted at `https://mcp.sentry.dev/mcp`, OAuth; "primarily designed for human-in-the-loop coding agents". Skills `inspect`, `seer`, `triage`, `project-management`; narrow with `?skills=inspect,triage`. Stdio mode uses a user auth token with read scopes `org:read, project:read, team:read` and write scopes `project:write, team:write, event:write`. Self-hosted supported via `--host`; Seer not available self-hosted. Claude Code plugin adds a `sentry-mcp` subagent. `[fetched]` — [getsentry/sentry-mcp](https://github.com/getsentry/sentry-mcp)

## Key Question 4: Claude Agent SDK and Managed Agents vs the Messages API inside the product (career coach chat, apply assistant, listing-verification agent)

### Takeaway
Use the plain Messages API (with tool use, prompt caching, and the client SDK's tool runner) for the user-facing career-coach chat and apply assistant; reserve the Agent SDK for internal/ops agents that need a filesystem and shell (e.g. a listing-verification worker that fetches pages, runs scripts, and writes reports), and treat Managed Agents (beta, `managed-agents-2026-04-01` header) as the way to run that worker without owning a sandbox — but note it is not ZDR/HIPAA eligible and adds a per-session-hour runtime fee (third-party figure $0.08/hr; not verified on Anthropic's pricing page).

### Cited Findings
- Anthropic's comparison table: Agent SDK = "Embed Claude Code's agent in your own Python or TypeScript application, in a process you operate"; Client SDK = "Call the Claude API directly ... You write the tool loop yourself, or let the client SDK's beta tool runner drive it"; Managed Agents = "Have Anthropic host the agent ... sessions in an Anthropic-managed cloud sandbox or a self-hosted sandbox". `[fetched]` — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- Agent SDK capabilities: built-in tools (read/write/edit files, run commands, web search), hooks, subagents, MCP, permissions, sessions (resume/fork), skills/commands/memory loaded from `.claude/`, plugins. `[fetched]` — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- Licensing/billing restriction: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods". Branding: products may say "Powered by Claude" but not "Claude Code". Governed by Anthropic's Commercial Terms. `[fetched]` — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- TypeScript package `@anthropic-ai/claude-agent-sdk`; entry `query({ prompt, options })` returning an async generator; options include `allowedTools`, `disallowedTools`, `permissionMode` (`default|acceptEdits|bypassPermissions|plan|dontAsk|auto`), `canUseTool` callback, `mcpServers` (stdio/sse/http/in-process `sdk`), `hooks`, `agents`, `systemPrompt` (preset `claude_code` or custom), `maxTurns`, `maxBudgetUsd` ("stops the query when the client-side cost estimate reaches the given USD value"), `settingSources`. It "ships a native Claude Code binary as an optional dependency" (e.g. `@anthropic-ai/claude-agent-sdk-darwin-arm64`); SDK v0.3.191 bundles Claude Code v2.1.191; `bun build --compile` needs special handling. `[fetched]` — [Agent SDK TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Managed Agents: status **beta**, header `managed-agents-2026-04-01`, "enabled by default for all API accounts"; concepts Agent / Environment / Session / Events; built-in Bash, file ops, web search/fetch with domain allow/blocklists, MCP servers; scheduled deployments (cron); "Managed Agents is not currently eligible for Zero Data Retention or HIPAA Business Associate Agreement (BAA) coverage" because sessions are stateful server-side; MCP tunnels and "dreaming" are research preview. Also available on AWS and Google Cloud (Anthropic-managed). `[fetched]` — [Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)
- Managed Agents pricing per third parties: tokens at standard API rates plus "$0.08 per session-hour, tracked to the millisecond ... only accrues while the session status is running"; web search $10 per 1,000; no batch/fast-mode/data-residency discounts; launched in public beta 2026-04-08. `[snippet]` — [TrueFoundry](https://www.truefoundry.com/blog/claude-managed-agents-pricing); [Verdent](https://verdent.ai/guides/claude-managed-agents-pricing). Not found on the fetched Anthropic pricing page.
- Model prices (per MTok, input / cache-hit / output): Fable 5.1 $10 / $0.25 / $50; Opus 5.5 $4 / $0.20 / $20; Sonnet 5.5 $2 / $0.10 / $10; Haiku 5.5 $0.10 / $0.01 / $0.50 (≤100k-token prompts), $0.50 / $0.05 / $2.50 above 100k. Batch API: 50% off input and output (e.g. Sonnet 5.5 $1 / $5). `[fetched]` — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Claude Code itself (and thus the Agent SDK) uses prompt caching and compaction; thinking is always on for Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable; effort levels control cost on adaptive models. `[fetched]` — [Manage costs](https://code.claude.com/docs/en/costs)
- The Claude Code GitHub Action "is built on the SDK". `[fetched]` — [GitHub Actions docs](https://code.claude.com/docs/en/github-actions)

### Inferences
- Career-coach chat and apply assistant: these are latency-sensitive, multi-tenant, per-user conversations with a small fixed toolset (fetch profile, search listings, draft cover letter). The Messages API with explicit tools, Sonnet 5.5 or Haiku 5.5, 1h prompt caching of the system prompt/rubrics, and streaming is the right shape; the Agent SDK's filesystem/shell loop, bundled CLI binary and ~Claude-Code-sized system prompt are overhead you'd pay per user turn. Also the SDK's terms forbid letting users log in with their own claude.ai accounts, so you'd be on API billing either way.
- Listing-verification agent (visit employer site, cross-check job posting, check domain age/WHOIS, produce a structured verdict): this is a long-running, tool-heavy, batchable job. Options in order of cost: (a) Messages API + Batch API (50% off) with your own fetch tools — cheapest if the checks are deterministic; (b) Agent SDK on Fly.io machines with `maxBudgetUsd`, `maxTurns`, `disallowedTools` and `settingSources: []` — when you want web search + scripts without hand-writing the loop; (c) Managed Agents when you don't want to run or sandbox the worker at all, accepting the beta label, the per-hour fee and the data-retention caveat (relevant for a career platform holding PII — many Nigerian/EU-style data-protection reviews will ask).
- Operational implications: Agent SDK processes spawn a CLI subprocess per query; size containers accordingly; pass `env: { ...process.env, ... }` (the `env` option replaces, not merges); pin SDK versions because each bundles a specific Claude Code version.
- Safety: any agent that reads third-party listing pages is exposed to prompt injection from those pages (see Q7); run it with no write tools against production data, allowlist domains for web fetch, and have it emit a verdict that a human or a second deterministic check gates.

### Gaps
- Official Managed Agents pricing (session-hour rate) was not present on the fetched platform pricing page; only secondary sources give $0.08/hour. Verify in Console before budgeting.
- No official guidance found on Agent SDK per-request token overhead (system prompt size) versus a bare Messages API call.
- Agent SDK rate-limit/throughput guidance for multi-tenant SaaS use was not found.

## Key Question 5: Engineering workflow (trunk-based + previews, conventional commits/changesets, semantic release, Renovate/Dependabot, Turborepo/Nx, Biome vs ESLint+Prettier, Husky/lefthook, TS project references, tsx, Vitest projects, Playwright sharding, Storybook, OpenAPI via Hono + Scalar, ADRs)

### Takeaway
For two people on one npm workspace: trunk-based with preview deploys, Biome 2 as the single formatter/linter (ESLint only if a Next.js-specific rule is indispensable), lefthook or Husky + lint-staged (either is fine), TypeScript project references with `tsc -b`, Vitest `test.projects` in one root config, Playwright sharded by GitHub matrix with blob reports merged, `@hono/zod-openapi` + Scalar for API docs, Renovate with grouped PRs, changesets only if `packages/core` is published outside the repo (otherwise skip), MADR-style ADRs in `docs/adr/`; defer Turborepo/Nx until CI time or caching actually hurts.

'blob' : 'html'`; `fullyParallel: true` balances shards by test rather than file. `[fetched]` — [playwright test-sharding-js.md](https://raw.githubusercontent.com/microsoft/playwright/main/docs/src/test-sharding-js.md)
- **Hono OpenAPI**: `@hono/zod-openapi` (`OpenAPIHono`, `createRoute`, `app.openapi(route, handler)`, `app.doc('/doc', ...)`, OpenAPI 3.1 via `doc31()`, `hide: true`), with type-safe client `hc<typeof appRoutes>()` from `hono/client`; validates only JSON/form bodies with a Zod schema (415 otherwise); mount small `OpenAPIHono` instances with `.route()` to avoid type-check slowdowns. `[fetched]` — [@hono/zod-openapi README](https://github.com/honojs/middleware/blob/main/packages/zod-openapi/README.md). Scalar: `@scalar/hono-api-reference` `Scalar()` middleware mounted at e.g. `/scalar` pointing at `/doc`; note config key differences (`url` vs `spec: { url }`) between versions. `[snippet]` — [Hono Scalar example](https://hono.dev/examples/scalar); [Scalar Hono integration](https://scalar.com/products/api-references/integrations/hono)
- **TypeScript project references**: referenced projects need `composite`, `declaration`, all files in `include`/`files`; `tsc -b` builds referenced projects in dependency order, rebuilds only out-of-date ones, and behaves as if `noEmitOnError` is on; dependents consume `.d.ts` outputs, so build after clone (or rely on editor in-memory generation). `[fetched]` — [TypeScript handbook: Project References](https://raw.githubusercontent.com/microsoft/TypeScript-Website/v2/packages/documentation/copy/en/project-config/Project%20References.md)
- **Lefthook vs Husky**: Lefthook (Go, parallel, no Node needed, `root` option scopes a command to a subdirectory so it "only fires when files in that directory are staged") vs Husky (~5M weekly downloads vs ~400K; usual pairing Husky + lint-staged); "if you already use Husky, there's no strong reason to migrate". `[snippet]` — [pkgpulse](https://www.pkgpulse.com/guides/husky-vs-lefthook-vs-lint-staged-git-hooks-nodejs-2026); [recca0120](https://recca0120.github.io/en/2026/03/08/lefthook-git-hooks/)
- **Renovate vs Dependabot**: Renovate `packageRules` group by regex/update type/schedule and support auto-merge with fine control; Dependabot grouping in `dependabot.yml` by name pattern, dependency type, semver level, and (per one source, GA mid-2025) across ecosystems; common recommendation "Renovate if you have a monorepo, use lockfiles, need custom grouping ... Dependabot remains the simpler option for small, single-repo GitHub projects." `[snippet]` — [appsecsanta](https://appsecsanta.com/dependabot-vs-renovate); [devopsboys](https://devopsboys.com/blog/renovate-vs-dependabot-dependency-updates-2026)
- **ADRs**: capture decision + context + consequences; Nygard's template is "simple and popular"; MADR offers simple/elaborate templates; practices: one decision per file, don't alter accepted ADRs — amend or supersede; record dates. `[fetched]` — [joelparkerhenderson/architecture-decision-record](https://github.com/joelparkerhenderson/architecture-decision-record)
- Claude Code specifics that touch the workflow: the GitHub Action restores `.husky/` from the base branch but not `package.json`, so pre-commit hooks that run package scripts in CI are a prompt-injection vector — "Invoke tools directly with pinned versions". `[fetched]` — [claude-code-action security](https://github.com/anthropics/claude-code-action/blob/main/docs/security.md). Code-intelligence plugins make the language server report type errors after edits. `[fetched]` — [Manage costs](https://code.claude.com/docs/en/costs)

### Inferences
- Trunk-based + previews: Vercel preview deployments (or Fly review apps) per PR plus the Claude GitHub Action review and Playwright shards give a fast loop; branch protection with required checks (`typecheck`, `biome ci`, `vitest`, `playwright`) is enough process for two people.
- Biome: pick Biome 2 for formatting + linting across all four packages with one `biome.json`; Next.js's `eslint-config-next` rules (e.g. `@next/next/no-img-element`, React hooks rules) are the main gap — Biome ships React-hooks and a11y rules, but verify the few Next-specific ones you care about; if indispensable, run ESLint only in `apps/web` and `apps/admin` with `eslint-config-next` and let Biome format. Don't run both Prettier and Biome.

- Changesets/semantic-release: `packages/core` is consumed in-repo by workspace apps; it never needs a published version, so skip changesets and semantic-release; use conventional commits (cheap, Claude writes them well via the Commit Commands plugin) and a `CHANGELOG.md` generated by `git-cliff` or release-please only if you need customer-facing release notes.

- Hooks: Husky + lint-staged if already known; lefthook if you want per-package `root` scoping and parallel Biome + typecheck. Keep the hook light (format + lint staged); let CI do tests.
- API docs: `@hono/zod-openapi` gives OpenAPI + runtime validation from the same Zod schemas in `packages/core`, Scalar at `/reference`, and `hc<>` typed client for the Next.js apps — one source of truth that also helps Claude (it can read `/doc`).

## Key Question 7: Security of AI-assisted development (prompt injection via repo content and fetched pages, secrets in sessions, reviewing AI-written migrations/RLS, security audits, Socket.dev, Semgrep SAST, DAST)

### Takeaway
Treat everything Claude reads (repo files, PR bodies, fetched pages, database rows via MCP, listing pages your agent scrapes) as untrusted input: run in Manual/auto mode with deny rules for `.env`, use WebFetch's summarised fetch rather than `curl`, keep write-capable MCPs out of `claude -p`/CI, pin tools in hooks, require human review of every migration and RLS policy (with a `supabase db diff` + RLS test gate), and add Socket (free: 1,000 scans/mo, 3 members) and Semgrep CE (`semgrep ci`, LGPL, free) to CI; DAST (ZAP) is optional until there's a public API surface worth scanning.

### Cited Findings
- Claude Code's prompt-injection safeguards: permission system; network commands (`curl`, `wget`) "are not auto-approved by default"; "For most fetches, WebFetch runs a separate model call over the page, and Claude receives that call's answer instead of the raw page"; command-injection detection ("asks before running a Bash command it can't fully analyze"); fail-closed matching; workspace trust dialog; `.mcp.json` approval prompt (skipped in `-p`). Best practices: "Avoid piping untrusted content directly to Claude", "Use virtual machines (VMs) to run scripts and make tool calls, especially when interacting with external web services". "While these protections significantly reduce risk, no system is completely immune". `[fetched]` — [Security](https://code.claude.com/docs/en/security)
- Hook `additionalContext` should stay factual "since imperative-sounding text can trigger prompt-injection defenses". `[fetched]` — [hooks reference](https://code.claude.com/docs/en/hooks)
- Credentials: API keys/tokens stored in macOS Keychain, or a `0600` file on Linux; credentials in MCP headers/env are redacted in some output; `.mcp.json` can't exfiltrate `ANTHROPIC_API_KEY` via `${VAR}`; cloud uploads leave uncommitted `.env`, `*.tfvars`, `id_rsa`, `*.pem` on the machine (macOS/Linux/WSL). `[fetched]` — [Security](https://code.claude.com/docs/en/security); [MCP docs](https://code.claude.com/docs/en/mcp); [cloud sessions](https://code.claude.com/docs/en/claude-code-on-the-web)
- Sandboxing: "Sandbox bash commands with filesystem and network isolation"; "In Manual mode, Claude Code asks you before its file tools read or write outside the folder where it was started", but "a Bash command you approve can still write anywhere your user account can" — OS-level restriction needs sandboxing. Accept-Edits mode auto-approves edits and a fixed set of filesystem commands. `[fetched]` — [Security](https://code.claude.com/docs/en/security)
- Data retention/training: limited retention, restricted access to session data; consumer users control training preferences in privacy settings; Commercial Terms apply to Team/Enterprise/API, Consumer Terms to Free/Pro/Max. `[fetched]` — [Security](https://code.claude.com/docs/en/security)
- GitHub Action prompt-injection controls: hidden text stripped "but bypasses may exist"; `include_comments_by_actor`/`exclude_comments_by_actor`; never check out untrusted PR heads into the workspace root under `pull_request_target`; `show_full_output` off on public repos; package scripts in hooks can run PR-controlled code. `[fetched]` — [claude-code-action security](https://github.com/anthropics/claude-code-action/blob/main/docs/security.md)
- MCP-specific: Supabase MCP has `read_only` and `project_ref` scoping and a README "Security risks" section `[fetched]`; Resend MCP warns about prompt-injected attachment exfiltration and offers `--allowed-file-dirs` `[fetched]`; Playwright MCP "is not a security boundary" and has an RCE-equivalent tool `[fetched]`; Paystack MCP refuses live keys `[fetched]`.
- `/security-review` is a bundled command for "an on-demand security pass over the changes on your current branch"; `security-guidance` plugin reviews Claude's own changes in-session. `[fetched]` — [Security](https://code.claude.com/docs/en/security)
- Plugins run with full user privileges outside permission rules and sandbox; review `hooks/hooks.json`, `.mcp.json`, `bin/`. `[fetched]` — [Plugin security](https://code.claude.com/docs/en/plugins/security)
- Hosted Code Review reads `REVIEW.md` "from the base or default branch and never from the pull request's own changes" (an anti-injection design); reviews are read-only and don't run your code. `[fetched]` — [Code Review](https://code.claude.com/docs/en/code-review)
- Socket: Free plan "$0 per developer per month ... unlimited developers and repositories, 1,000 scans per month, 3 members"; Team $25/dev/mo, Business $50/dev/mo (20% off annual); one tracker claims the free dependency cap rose to 10,000 in July 2026 (unverified). `[snippet]` — [socket.dev/pricing via search](https://www.socket.dev/pricing); [usagepricing](https://usagepricing.com/blueprint/activity/socket-2026-07-29-free-tier-dependency-limit)
- Semgrep CE: "open-source program analysis engine", LGPL-2.1; `semgrep ci` scans code and dependencies; registry of "2,000+ community-driven rules"; CE "can only analyze code within the boundaries of a single function or file"; login unlocks Pro rules, Pro engine (cross-file) and Supply Chain; remote configs send pseudonymous metrics unless `--metrics=off`. `[fetched]` — [semgrep/semgrep](https://github.com/semgrep/semgrep). Paid Teams plan ~$30-40/contributor/month; free-tier limits reported as 10 contributors and either 50 or 10 private repos (sources conflict). `[snippet]` — [pricingsaas](https://pricingsaas.com/companies/semgrep/diffs/2026W10); [costbench](https://costbench.com/software/ai-code-review/semgrep/free-plan/)
- Supabase skills explicitly cover "security audits" and "Security & RLS (Critical)". `[fetched]` — [supabase/agent-skills](https://github.com/supabase/agent-skills)

### Inferences
- Repo-content injection: the realistic vectors for this team are (1) third-party PRs/issue comments feeding the GitHub Action, (2) dependency READMEs/`node_modules` Claude reads, (3) job-listing pages fetched by the verification agent, (4) user-generated rows returned by the Supabase MCP. Mitigations map directly: Action write-access gating + comment filters; `Read` deny on `node_modules/**` is impractical, but keep WebFetch (summarised) over `curl`; agent runs with no write tools and domain allowlists; Supabase MCP read-only against non-production refs and never pasting raw rows into prompts without delimiting.
- Secrets: keep `.env*` denied, use Supabase CLI/Vercel/Fly CLIs that read their own auth stores rather than exporting keys into the shell Claude uses; in cloud sessions use network secrets, not environment variables.
- Migrations and RLS: AI-written SQL is the highest-impact failure mode for a platform holding CVs and payment records. Gate: every migration via PR; `supabase db diff` output in the PR; a Vitest project that runs RLS tests against a local Supabase (anon vs authenticated vs service role) on each PR; Claude's `/new-migration` skill must include a checklist (RLS enabled on new table, policies for select/insert/update/delete, `security definer` functions reviewed, no `service_role` key in client code); the Supabase postgres-best-practices skill supplies the rules.
- "securitymaxxing-style" audits: since that plugin is unverifiable, use `/security-review` on each branch, `security-guidance` in-session, and periodic OWASP-oriented prompts; for anything real, Semgrep CE + Socket in CI are deterministic and free.
- DAST: skip until the Hono API is public; then OWASP ZAP baseline scan against a preview URL as a weekly scheduled job is enough.

### Gaps
- No Anthropic-published data on prompt-injection success rates in Claude Code; the docs explicitly say protections are not complete.
- Semgrep and Socket free-tier limits are from aggregators with conflicting figures (vendor pages blocked).
- No official Supabase guidance text on reviewing AI-generated RLS was retrievable (DNS-blocked); recommendations above are inferred from the skills' scope and general practice.

## Synthesis: the smallest set that pays for itself, and what to skip

### Takeaway
Adopt about a dozen things; explicitly skip another dozen until a measurable pain appears.

### Cited Findings
- All items below are drawn from the fetched sources cited in Q1-Q8 (Claude Code docs on memory, hooks, permissions, skills, subagents, plugins, plugin evals, GitHub Actions, cloud sessions, costs, security; vendor MCP READMEs for Supabase, Sentry, PostHog, Resend, Playwright, Paystack, Context7, GitHub, Cloudflare; Figma MCP guide; Vitest, Playwright, Hono, TypeScript, Semgrep, Changesets, ADR sources).

### Inferences
**Adopt now**
1. Root `CLAUDE.md` (<200 lines) + `.claude/rules/{api,web,db}.md` with `paths:`; `/doctor prompt-audit` quarterly. (Q1)
2. Committed `.claude/settings.json`: allow `Bash(npm run *)`, `Bash(npx vitest *)`, `Bash(npx biome *)`, `Bash(npx tsc *)`, `Bash(gh pr *)`, `Bash(supabase db diff *)`; deny `Read(./.env)`, `Read(./.env.*)`, `Bash(curl *)`, `Bash(wget *)`, `Bash(git push --force *)`; `WebFetch(domain:...)` for docs. (Q1)
